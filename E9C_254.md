# E9c: 254-device stochastic batches, 150 stratified nodes

User-authorized adjustment, separate from e9c_first. All voltage samples are retained for every selected device. Every update selects 254 training devices without replacement within the batch, with a fresh selection at the next update. The 150 spatial samples preserve the stored pool's proportions: 90 of 150 junction nodes, 15 of 25 at each edge, and 30 of 50 remaining interior nodes. Ordered strata preserve coverage; region extremes are included. Node selection is shared across all voltages of a device in an update. Control and PKC use identical random plans.

Accumulation streams row chunks onto the GPU, weighting each chunk by its row count. Therefore neither optimizer batch size nor loss changes with chunk capacity. Longer voltage curves keep their existing greater weight. Local full-vs-streamed gradients agree to relative error below 1e-14 on a two-device all-voltage test. Window and sample counts were verified for all 1731 stored devices (1384 train, 175 validation, 172 test).

Real run entry: m6d.run_training. One seed (0), Control on GPU 0, PKC on GPU 1. Same deterministic data pretraining, 2000 Adam updates, up to 500 L-BFGS iterations. Initial/final logs and every 50 updates (L-BFGS: evaluations). L-BFGS uses a fixed all-train spatial plan, 4,409,850 rows, with gradient accumulation. Sampling changes the objective from the earlier uniformly subsampled 32-node pilot; no claim of measured superiority. Runtime budget must be decided from the rehearsal before launching this expensive run. m6d retains deadline handling; a truncated run is not a completed 2000/500 experiment.

Capacity smoke entry: m6_capacity.run_smoke. Full dataset and production 256x5 float64 network, one arm per T4. Probe resident row-chunk capacity until caught CUDA OOM (or explicit probe cap); record every attempt and a conservative successful chunk. One identical data warm-up, two Adam updates on 254 devices, closure benchmarks at 254/508/1016/1384 devices, then two real L-BFGS iterations on all train with strong Wolfe. These are performance/stability measurements, not accuracy evidence. Report runtime scenarios for the requested 2000/500 configuration, excluding pretraining; record actual closure count separately from optimizer iterations. GPU-side memory results cannot be inferred from the local CPU smoke.
