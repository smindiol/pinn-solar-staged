# Terminal-current supervision pilot (implementation prepared, not launched)

User decision: 64 devices for Adam and a fixed 64-device L-BFGS set, 75 spatial nodes, all voltages. Network256x5 float64, physical scaling and PKC retained. New module m6_current_fit.py; existing runs untouched. No local training/tests executed, following user instruction. Requires remote smoke before performance/accuracy claims or a long run.

Three variants: base (current data loss), terminal (add terminal JV), balanced (terminal JV plus separate potential/current/terminal weights). Same seed0 random initialization, stochastic device/spatial plans and schedules. Each variant now has its own 300-step DATA pretraining under its corresponding supervision; this tests the full training strategy. It intentionally differs from the previous shared-checkpoint resolution pilot. Default refinement100Adam; LBFGS off for initial screening. Production can explicitly request adam_steps2000,lbfgs_iters500; not yet submitted. Logs first/final/every50 updates; LBFGS every50 evaluations.

JV = average over devices of voltage-mean squared terminal-current error, normalized by J0*Jgen. Prediction at x=0 is already dimensionless J/Jgen. Evaluated once per device-voltage, not per spatial node. Original spatial MSEs keep their row-weighted convention. Separate data-group weights use inverse group gradient norms relative to potentials, capped to [.01,100], calibrated on a common clean training plan at random initialization and again after data pretraining. Physical weights use existing Eq39 after pretraining. All weights fixed within each optimizer phase and across LBFGS closures. Norms and calibration values persisted; this heuristic is an ablation, not a guarantee of balanced optimization.

Noise default OFF. Optional include_noise=True adds a fourth variant balanced+noise, sigma=.005 in terminal J/Jgen units (0.5% of generation current), only to terminal training labels during pretraining/Adam. Deterministic draw per plan, independent between updates. No perturbations to parameters, coordinates, stored files, physical residuals, boundary conditions or validation. LBFGS always uses CLEAN fixed targets. This is a pragmatic robustness ablation, not a model of dPV numerical uncertainty or a proposed repair for underfitting. Other targets remain clean, which must be disclosed when interpreting it.

Reason for default OFF: for clean target y and independent zero-mean target noise epsilon, E[(f-y-epsilon)^2]=(f-y)^2+Var(epsilon); expected gradient/optimum do not change. Finite-step optimization can change via gradient variance. Input-noise regularization results must not be presented as proof that terminal-label noise regularizes this model. Bishop1995 primary source: https://www.microsoft.com/en-us/research/publication/training-with-noise-is-equivalent-to-tikhonov-regularization/ . Not verified as an optimal noise level for this dataset.

Evaluate clean validation after pretraining, after Adam, and final: all175 devices, all voltages, all250 stored spatial nodes, JV loss and five residuals; retain per-material JV/PCE/Jsc and invalidVoc counts. Success requires an improved whole-curve error and fewer invalidVoc, with physical residuals disclosed rather than optimizing Jsc alone. No assumed benefit, no significance claim with one seed. Need remote smoke to verify units, finite gradients, loss accounting and deterministic LBFGS before launch.
